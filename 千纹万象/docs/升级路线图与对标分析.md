## 一、评分依据：官方怎么说的（原文摘录）

来源：《2026 年第十四届全国大学生数字媒体科技作品及创意竞赛参赛指南》与
[大赛官网](https://www.cmit.cn/)、[民族文化赛项作品展示](https://www.cmit.cn/html/minzuwenhua/list-317-1.html)。

### 1.1 民族文化赛道「评审重点」（指南 p.7，原文）

> **重点关注文化理解、资料依据、数字表达创新、艺术表现质量、交互体验、传播适配性和文化传承价值。**

七个维度逐一拆解，并对照我们当前的完成度：

| 评审维度 | 官方措辞的要害 | 我们目前的对应 | 缺口 |
|---|---|---|---|
| 文化理解 | 「尊重文化主体和文化语境」 | 六大谱系 + 11 构成法则考据 | 已较强 |
| **资料依据** | 「注重资料来源、文化语境」 | 真迹图版逐张标注来源；新增纹博士知识库逐条 `src` | **本次升级重点补强** |
| 数字表达创新 | 「数字影像、虚拟现实、交互设计、融合出版」 | 参数化生成引擎（11 骨架）+ AI 协同 | 已较强 |
| 艺术表现质量 | 「艺术表现质量、视觉风格」 | 真迹版式 + 绢帛印章视觉体系 | 已较强 |
| **交互体验** | 独立成项 | 原为"选—定—配—调"表单式交互 | **本次升级重点补强** |
| 传播适配性 | 「传播适配性」 | 纹样密码分享、PNG/SVG 导出 | 待补 |
| 文化传承价值 | 「创造性转化和创新性发展」 | 真迹 → 算法 → 器物 → 文创闭环 | 待补 |

### 1.2 作品要求的两条硬约束（指南 p.7，原文）

> （2）作品应尊重文化真实性和表达规范，注重资料来源、文化语境、视觉风格和传播对象。
> （3）涉及特定民族文化资源的，**应避免脱离语境的符号拼贴和不当使用**。

> （3）涉及历史人物、事件、文献、影像和档案材料的，**应注明来源**；不得虚构、歪曲或不当娱乐化呈现重大历史内容。

**这两条正是"接个大模型随便聊"会踩的雷**：模型凭参数记忆讲纹样史，极易年代错置、
寓意张冠李戴，客观上就是"脱离语境的符号拼贴"。这是本次「纹博士」设计的出发点。

### 1.3 AI 使用原则（指南 p.16–17，原文）

> 1. 参赛团队应在统一的《人工智能工具使用情况说明》中勾选"使用"或"未使用"……使用的，应填写工具名称、使用环节、主要工作流、**人工筛选修改、团队原创贡献**及版权和数据合规情况。
> 2. 涉及生成合成内容的，应按照国家有关规定进行标识。
> **3. 使用人工智能工具本身不作为简单加分或扣分依据，评审重点为作品原创构思、团队实质性贡献和人机协同质量。**
> 4. 未如实披露人工智能工具使用情况、无法说明作品形成过程或**明显缺少学生团队实质性贡献**的，按参赛纪律处理。

**结论：AI 不是加分项，也不是减分项；「团队实质性贡献」和「人机协同质量」才是。**
→ 所以纹博士的核心不在"能聊天"，而在"检索排序算法是团队自研的、事实底座是团队考据的"。

### 1.4 评分方式（指南 p.16，原文）

> 竞赛采用**百分制**和分类评价方式。校级初赛和选拔赛主要依据参赛材料进行评审；
> 全国总决赛原则上采取作品展示、现场演示、专家评审和答辩交流相结合的方式。
> 具体评分指标、分值、同分处理和评审记录要求，以**《评分标准及奖项设置》**为准。

> 4. 全国总决赛每个评审组由 3 名来自不同单位的赛项相关的产业/行业专家组成，
> 采取**独立评分、现场问答和集体复核**相结合的方式评审。

**行动项：** 明细权重在单独的《评分标准及奖项设置》文件中，**官网未见公开下载**。
建议向赛区联系人索取，或按上表七维度均衡投入（当前策略）。

## 二、同类优秀作品怎么做（官网实例）

从 [民族文化](https://www.cmit.cn/html/minzuwenhua/list-317-1.html)、
[科幻创意](https://www.cmit.cn/html/kehuanchuangyi/list-257-1.html)、
[AIGC](https://www.cmit.cn/html/aigc/list-318-1.html) 三个类目梳理出的规律：

| 获奖作品 | 类别/年份 | 做法 | 对我们的启示 |
|---|---|---|---|
| [**中华民族服饰大模型的生成与应用**](https://www.cmit.cn/html/minzuwenhua/show-317-3911-1.html) | 民族文化 | 自建民族服饰数据集 + **领域大模型** | 我们已有 115 幅真迹库 → 可升级为"纹样领域知识检索（RAG）" |
| [**纹样猎手**——民族传统纹样数字实景收集类游戏](https://www.cmit.cn/html/minzuwenhua/show-317-3994-1.html) | 民族文化 | **游戏化收集**机制 | 交互体验维度的对标：我们缺"机制性玩法" |
| [**古韵青花**——基于 TouchDesigner 的青花瓷主题交互设计](https://www.cmit.cn/html/kehuanchuangyi/show-257-4195-1.html) | 科幻创意·**国赛一等奖** 2025 | **九大交互场景**、Kinect 手势/摄像头感应/键盘多维交互、点云+粒子实时渲染 | "多模态交互 + 实时动效"是拿一等奖的形态；我们目前以点击/表单为主 |
| [**敦煌雅韵·声香秘境**](https://www.cmit.cn/html/minzuwenhua/show-317-4224-1.html) | 民族文化 | **多感官**（声、香） | 我们可补"纹样音律"（把骨架转成节奏） |
| [**交互《使者》**](https://www.cmit.cn/html/minzuwenhua/show-317-3618-1.html) | 民族文化·国赛一等奖 2023 | 绘画+音效+交互讲一个故事，"占领受众心智" | 叙事化包装比功能罗列更能得分 |
| [**青檐浮笺**](https://www.cmit.cn/html/minzuwenhua/show-317-4115-1.html)、[**指尖传译·藏文密码**](https://www.cmit.cn/html/minzuwenhua/show-317-4167-1.html)、[**辽瓷艺术数字化资源 APP**](https://www.cmit.cn/html/minzuwenhua/show-317-4072-1.html) | 民族文化 | 非遗**数字化资源库 + APP 化** | 我们的"纹库"可延伸为可检索的**数字资源库** |

**共性规律（三条）：**

1. **要有"机制"，不能只有"功能"** —— 收集、闯关、成长、解锁这类机制带来停留时长；
2. **要多感官/多模态** —— 视觉之外补听觉（音效、解说、音律）是常见加分手法；
3. **文化数据要"自建成体系"** —— 自建数据集/知识库被视为团队的实质性贡献。

陶瓷（青花/辽瓷/青铜/瓦当）6 件、中医药 5 件、皮影/木偶/傩戏 4 件、敦煌题材 6 件、
古建/园林 4 件、服饰 3 件、汉字/方言 3 件。
—— **「纹样本身作为可生成的对象」只有我们一件**；其余多是"某类非遗的展示/科普/文创"。
这是本作品最硬的差异化立论，答辩与文档中应更前置地强调。

**复访后的三条新结论**

1. **叙事线缺失是最大短板**：本届一等奖作品几乎都在"讲一个故事"（蓝花坊讲蜡染传承、
   交互《使者》讲一个故事）。建议给 8 视图加一条**贯穿叙事**（如"一位织工/画师的一天"
   或"一幅纹样从真迹到器物的旅程"），把功能串成旅程，而非并列罗列。
2. **"限时挑战"与"纹样对比"是两个低成本高回报的机制补强**（对标纹样猎手）：
   现有收藏册已有进度/徽章，加"纹样对比"（并排两幅真迹的谱系/构成/配色对照）几乎零成本。
3. **多模态仍是我们与顶级作品的差距**：听觉已补（听·纹律 + 语音解说），
   视觉以外的维度（摄像头手势/陀螺仪/触觉）尚未触及。Web 端可低成本尝试的只有
   **陀螺仪视差**与**麦克风节拍驱动织排**，需评估现场演示稳定性后再定。

## 三、本次已完成的升级：纹博士 · 悬浮对话导览

### 3.1 为什么这样设计

用户提出"引进悬浮窗口、接入 AI、支持对话增进纹样知识了解"。直接照做（塞一个
聊天框调用大模型）会同时踩三个坑：

- **踩坑 1（合规）**：模型凭记忆讲纹样史 → 幻觉 → 违反"避免脱离语境的符号拼贴"；
- **踩坑 2（评分）**：AI 调用不加分，"接个 API"还说不出团队贡献 → 违反"团队实质性贡献"；
- **踩坑 3（演示）**：现场无 Key / 断网 → 聊天框直接瘫痪。

因此设计成 **"团队考据库 + 自研检索 + 大模型组稿"** 的三层结构：

```
用户提问
   ↓
① 自研检索（js/guides.js）       ← 团队实质性贡献：中文 bi-gram 倒排索引 + IDF 打分
   ↓  取出 3~6 条带出处的考据资料
② 事实底座（js/knowledge.js）    ← 团队考据：6 大部分 40 余条，每条带 src
   + 真迹纹库（js/plates.js）    ← 115 幅真迹的器物考/寓意
   ↓  组装成"资料包"
③ 大模型（js/llm.js）            ← 只负责把资料组织成口语化讲解（温度 0.6）
   ↓
回答 + 「资料依据」可逐条点开 + 真迹跳转
```

**关键约束写进了系统提示词**（`Guides.systemPrompt`）：

> 涉及纹样的年代、器物、寓意、出处等事实，**只能使用下面【资料包】里的内容**；
> 资料包里没有的，就不要说……**严禁编造**：不确定的年代、书名、馆藏、人物一律不提。
> 宁可少说，不可说错。

**三重降级链**，保证任何环境下都能演示：
有大模型 Key → 对话式讲解；无 Key / 调用失败 → **本地考据摘录**（明确标注"未调用大模型"）；
库中无相关资料 → 诚实说"没有可靠资料"，并引导去纹库或换问法。

### 3.3 检索质量实测

用 20 条**真实用户口吻**的提问做回归，命中 20/20：

```
✓ 蝙蝠纹有什么寓意      → 蝠 · 福 / 动物纹样 / 植物纹样 …
✓ 四只蝙蝠代表什么      → 蝠 · 福 / 动物纹样 …
✓ 宝相花的来历          → 宝相花 · 庄严圆满 / 盛唐 · 宝相花与团窠 …
✓ 青花瓷为什么只用蓝色  → 青花瓷
✓ 补子的品级            → 动物纹样 / 明清 · 图必有意 … / 鹤 · 寿
✓ 海水江崖用在衣服哪里  → 海水江崖 · 江山永固 / 云水纹样
✓ 真迹图版的版权        → Owen Jones《Examples of Chinese Ornament》(1867) …
✓ 你们用的算法是什么    → 构成法则的程序化依据 / 适合纹样 …
```

同时**离题提问会被正确拒绝**（"今天天气怎么样" → 无资料 → 回退兜底话术），
这正是"避免脱离语境的符号拼贴"在交互层的落地。

### 3.4 对话质量实测与调参（2026-10-03）

系统提示词最初写成了"资料包里没有的就不要说""**宁可少说，不可说错**"。
用真实网关跑了一批真实口吻的提问后，发现**约束过死反而让 AI 变得没用**：

| 提问 | 过紧版的表现 | 问题定性 |
|---|---|---|
| 为什么中国纹样这么讲究对称？ | "这一点我手头没有可靠资料，不敢乱说"——把一个人人能谈的好问题顶了回去 | **该答不答** |
| 你觉得哪个朝代的纹样最好看？ | 绕着走，不敢表达偏好 | 该答不答 |
| 帮我起个带莲花意象的名字 | **返回空**（模型没敢生成） | 该答不答 |
| 宝相花是什么？ | 能答，但是百科词条式罗列，没有聊天感 | 表达僵硬 |

**根因**：把"事实准确"和"什么都不敢说"混为一谈了。正确的分界是——

> **事实**（年代／器物／寓意／书名／馆藏／人物）→ 必须来自资料包，不许编；
> **理解、审美、联想、建议、感受** → 尽管聊，这正是"讲解员"的价值所在。

改后的提示词只死守"不编造具体信息"这一条，并明确鼓励"别因为资料包没写就不敢说话"。
同一批问题复测：全部作答，平均 231~259 字，语气自然，且**依然没有编造**——
因为事实仍被资料包锚定。这证明"可溯源"与"会聊天"并不矛盾。

**同期修掉的技术问题**（均为真实踩坑，已在代码注释中留痕）：

| 问题 | 现象 | 修法 |
|---|---|---|
| `buildContext` 里 `catName` 未定义 | 凡"命中真迹"的提问直接抛 `ReferenceError` 崩掉，而这恰是最常见情况 | 在函数内补定义 |
| **回答气泡被摘出文档** | 模型明明流式吐了 200+ 字，界面上却**永远看不到回答**——首块到达时 `holder.remove()` 把承载正文的节点摘掉了，之后再没插回去 | 改为行常驻 DOM，只替换内容 |
| SSE 只按 `\n\n` 切分 | 网关若用 `\r\n\r\n`，两个事件会粘成一块导致整段解析不出 | 先归一化换行再切分 |
| `choices` 为空的 usage 汇总块 | 曾被当成正常块处理 | 安全跳过 |
| `max_tokens` 给太小（原 600） | 该模型 **reasoning 与 content 共用额度**，问"为什么讲究对称"时思考吃掉全部额度 → `finish_reason=length`、正文为空、用户看到空气泡 | 见下节，直接给到模型上限 |
| 网关网络抖动 | 实测出现连接超时与 `ECONNRESET`（10 次里失败过 5 次的那一轮就是此因） | `chat()` 加退避重试（默认 2 次）；**只在"一个字都没吐出来"时重试**，已开始流式输出绝不重试，避免回答从头再来 |

### 3.5 最终定稿：撤掉全部约束，只保留身份

上文第二版仍属"带着镣铐跳舞"——只守"不编造具体信息"，但模型依旧在自我审查，
语气仍偏紧。经与作者确认，**最终版把约束全部撤掉，只交代身份，并按模型上限配置参数**。

**现在的系统提示词只有三段**：它是谁（纹博士 / 千纹万象讲解员 / 面对普通观众）、
手上有团队考据的资料包（优先采信、用上就标角标）、资料包内容。
连"不要编造"都不再作为禁令去压制它。

**参数按模型上限给**（`js/config.js`）：

| 参数 | 旧值 | 现值 | 说明 |
|---|---|---|---|
| `chatMaxTokens` | 600 → 3000 | **8192** | 直接给到模型输出上限；reasoning 与正文共用额度，给足才不会"想完就没额度" |
| `chatTimeoutMs` | 60s → 120s | **300s** | 不再因为怕慢而提前掐断 |
| `chatTemperature` | 0.6 → 0.7 | **1.0** | 模型默认值，措辞更活、更有讲解员个人风格 |
| 对话历史 | 只带最近 8 轮 | **全量** | 观众问到第八轮之后往往是真正深入的时候，最不该失忆 |
| `chatRetries` | 2 | 2 | 保留（网络自愈，非能力限制） |

**放开的实测收益**（同一批 10 个问题，含 4 个原版"答不了"的）：

| 指标 | 受限版 | 放开版 |
|---|---|---|
| 平均回答长度 | 231 字 | **601 字** |
| 「为什么中国纹样这么讲究对称」 | 「我手头没有可靠资料，不敢乱说」 | 765 字，从**适合纹样构图、圆满吉祥观、佛教联珠纹传入**三层展开 |
| 「帮我起个带莲花意象的名字」 | **返回空** | 给出莲生/宝相/缠莲/照水莲/并蒂五个方向并追问用途 |
| 「给咖啡品牌做纹样设计」 | （未测，原版几乎必拒） | 998 字完整提案：缠枝做杯套、适合纹样做"咖啡团花"、二方连续做封口带，还给配色建议 |
| 事实准确性 | 有据 | **仍有据**：模型主动引用图版 002/012/055 等真实图版，角标 7 处、资料依据 6 条 |

**关键发现：不设防也没有失控。** 因为事实由**检索层**保证——资料包是团队考据的，
模型倾向于采信并标注；放开的是表达自由度，不是事实来源。这恰好印证了
"约束应该放在检索层，而不是压在模型嘴上"。

**连带改动**：放开后模型自然开始用 `###`、`**加粗**`、`- 列表` 组织长回答
（这本身是好事，说明讲得有层次）。气泡原本是 `white-space: pre-wrap` 的纯文本，
星号井号会原样露出来。于是给 `_format()` 加了一个**极轻量 Markdown 渲染器**
（支持标题/无序/有序/加粗/斜体/行内代码，先转义再生成标签，无外部依赖），
而不是回头去禁止模型用 Markdown。

## 五、答辩话术（可直接用）

**问：你们这个对话窗口和"接个大模型聊天"有什么区别？**

> 区别在事实从哪来。我们不允许模型凭记忆讲纹样史——那必然出现年代错置和
> 寓意张冠李戴，而参赛指南明确要求"避免脱离语境的符号拼贴"。
> 所以事实层是我们自己考据的纹样知识库，40 余条，每条都标了文献依据；
> 检索层是我们自研的中文 bi-gram 倒排索引 + IDF 打分算法，负责从库里选出相关资料；
> 大模型只做最后一步——把资料组织成口语化讲解。
> 所以每一条回答下面都有「资料依据」，可以逐条点开核对原文与出处。
> 而且没有 API Key 也能用：自动切换为本地考据摘录，并明确标注"未调用大模型"。

**问：AI 在作品里占多大比重？**

> 指南第 16 页写明"使用人工智能工具本身不作为简单加分或扣分依据，评审重点为
> 作品原创构思、团队实质性贡献和人机协同质量"。所以我们主动划清边界：
> 织排构图、器物效果图、配色、动效、**以及纹博士的检索算法和知识库**——
> 全部是团队自研，无 AI 参与；大模型只承担"组织语言""充当解签人""实物渲染"
> 三类辅助角色，每一处都在页内和《AI 工具使用情况说明》里如实披露。

**问：为什么不做成 APP / VR？**

> 我们选择 Web 是刻意的：指南把"传播适配性"列为评审重点。
> 纯前端、免安装、双击即用，博物馆互动屏、课堂、手机都能直接打开，
> 生成的纹样还能导出 PNG/SVG 用于文创生产——这是传播与转化的最短路径。
> （若评委期待沉浸式形态，我们已在路线图中列出 WebXR 试纹与音律化的扩展方案。）

## 六、附：本次改动的技术备注（给后续维护）

1. **资源版本号已从 `?v=20261002i` 提升到 `?v=20261003a`**（共 17 处）。
   后续任何 js/css 改动都要再 bump，否则浏览器会吃缓存。
2. **纹博士的检索调参位置**：`Guides._weight()`（词元权重）、`Guides._charFloor`（冷门字门槛）、
   `search()` 里的 `score >= 2`（相关度下限）。三处共同决定"什么算命中"。
3. **新增知识条目只需编辑 `js/knowledge.js`**：必须带 `src`（出处）与 `tags`（检索词，
   建议把常见同义写法都列上，例如"四只蝙蝠"和"四蝠"）。索引会在首次检索时自动重建。
4. **`prefers-reduced-motion` 下的坑**：入场动画的 `from` **不能含 `opacity:0`**，
   否则在"减少动态效果"环境下 animation 被禁用，元素会永远停在透明态。
   本次已把终态放在基础规则里，动画只动 `transform`。
5. **切勿用 PowerShell `Get-Content`/`Set-Content` 改写含中文的源码文件**：
   中文 Windows 下默认按 GBK 读写，会把 UTF-8 中文不可逆地转成乱码
   （本次已因此损坏并重建过一次 `index.html`）。改用编辑工具或
   `[System.IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)`。
